Add your game

If your game runs in a browser, you can put it online yourself and it'll show up here. No command line, no git, nothing to install — you drag your files into a web page and that's the whole job. About ten minutes the first time, under a minute every time after.

  1. Get a GitHub account

    github.com → Sign up. It's free and stays free — this isn't a trial. Pick a username you don't mind people seeing, because it ends up in your game's address.

  2. Make a place for the game

    Click the + at the top right → New repository.

    A "repository" is just a folder that lives online. Name it after your game, lowercase with dashes instead of spaces — ninja-golf, not Ninja Golf. That name becomes part of the address, so keep it short.

    Leave it set to Public, and don't tick any of the boxes about README or licence files. Then Create repository.

  3. Drag your files in

    Add file → Upload files, then drag your game's files straight from your desktop onto the page. Folders work too — drop the contents of your game folder, not the folder itself.

    Then write anything in the little message box and hit the green Commit changes.

    The one thing that must be right: your main file has to be called exactly index.html, all lowercase. If yours is Game.html or main.html, rename it before you upload. Nothing else about the name matters, and this is the single most common reason a page comes up blank.

  4. Turn the website on

    This bit is hidden away, so follow it exactly:

    Settings (along the top of your repository) → Pages (down the left-hand side) → under Build and deployment, set Source to Deploy from a branch → set the branch to main and the folder to / (root) → Save.

    Give it a minute or two. Refresh the page and a green banner appears with your address.

  5. Send the address over

    It'll look like this, with your username and your repository name:

    https://your-username.github.io/your-game/

    Open it to check it actually works, then send it to me and I'll add a card for it on the Arcade.

    From then on it's trivial. To update your game, open the repository, Add file → Upload files, drop the new version over the top, commit. Live in about a minute. You never have to touch the settings again.

If something goes wrong

  • Blank white page. Nine times out of ten the main file isn't called index.html, or a filename's capitalisation doesn't match. Windows treats Sprites.png and sprites.png as the same file and the web does not — so if your code asks for sprites.png and the file is actually Sprites.png, it works on your machine and breaks online. Match them exactly.
  • Images or sounds missing. Same cause, or the folder structure changed during upload. Your files need to sit in the same arrangement they do on your computer.
  • A file won't upload. Dragging into the browser caps out at 25 MB per file. Anything bigger needs compressing, or a different route — ask and I'll sort it.
  • Nothing happens after Save. It can take a couple of minutes the very first time. If it's still nothing after five, check the repository is Public — Pages on a private one needs a paid plan.
  • It worked, then stopped. Every upload replaces what's there. Your old versions aren't lost, though — GitHub keeps every one of them, so nothing you do here is irreversible.

Don't fancy any of that? itch.io takes a single .zip with an index.html inside it and hosts browser games for free — no repositories, no settings pages. A link from there works just as well and I'll add it the same way.

Your game stays on your own account, under your own name. You can change it, break it, or take it down whenever you feel like it without asking anybody, and nothing here can reach into it.
